# GraphVisAgent 仕様書

**GraphVisAgent** は、ユーザーがネットワーク構造を対話的に可視化し、大規模言語モデル（LLM）との会話を通じて分析を行うための Web アプリケーションです。研究者や開発者が、専門的な知識なしにネットワークの特徴を把握し、インサイトを得ることを目的としています。

## 1. この仕様書の役割

この仕様書は **「なぜそうなっているか」** を記録します。**「何をするか」の唯一の情報源はコードです。**

### 書くもの

- 設計判断とその根拠、検討して却下した代替案
- 不変条件・契約と、それが必要な理由
- 意図を表す図（C4、シーケンス図、ER 図）
- 研究上の設計原則（Agent Policy）とその論拠

### 書かないもの — コードが宣言している事実

- エンドポイント一覧 / MCP ツール名の一覧 / DDL の列定義 / コンポーネント一覧 / パラメータ表
- 時点計測値（プロンプト文字数、テスト数、ツール数）
- セットアップ手順 → ルートの `QUICKSTART.md`
- リポジトリでの作業手順 → ルートの `AGENTS.md`

### 判定基準

> **「この記述はコードから機械的に導出できるか？」**
> Yes なら仕様書には書かず、コードを指す。

この規約は経験則ではなく、このリポジトリの履歴から得られた結論です。2025年に書かれた文書のうち、コードの列挙を複製していた部分（エンドポイント表、旧ツール名、DDL、コンポーネント一覧）は数ヶ月で例外なく実装と乖離しました。一方、C4 図・シーケンス図の意図・設計原則の記述は乖離しませんでした。経緯は [4_Decisions/0001-documentation-scope.md](./4_Decisions/0001-documentation-scope.md) を参照してください。

## 2. 仕様駆動開発の運用

**新機能とアーキテクチャ変更のみ**が仕様駆動の対象です。既存の実装を遡及的に仕様化することはしません。

1. 実装前に [4_Decisions/](./4_Decisions/) に短い ADR を書く（`0000-template.md` をコピー）
2. 実装する
3. 決定が既存の設計に影響する場合、該当する [2_Technical_Details/](./2_Technical_Details/) の文書へ根拠を反映する

## 3. 構成

| ドキュメント | 対象読者 | 内容 |
|---|---|---|
| [0_Executive_Summary/](./0_Executive_Summary/README.md) | 意思決定者、企画担当 | 目的、価値、ターゲットユーザー、システム全体像 |
| [2_Technical_Details/](./2_Technical_Details/) | 実装担当者、アーキテクト | アーキテクチャ、各コンポーネントの設計判断、契約、データモデルの設計意図 |
| [4_Decisions/](./4_Decisions/) | 実装担当者 | 個々の設計判断の記録（ADR） |

各ドキュメントには冒頭に **「前提知識レベル」** を明記しています。
