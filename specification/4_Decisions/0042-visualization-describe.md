# 0042. 描画の状態を、画像を見ずに数値で説明するツール

- **状態**: 採用
- **日付**: 2026-10-27
- **関連**: [0017](./0017-layout-quality-metrics.md), [0023](./0023-view-navigation-and-labels.md), [0024](./0024-bounded-tool-observations.md)

## 背景

エージェントが描画結果について受け取るのは、ノード数・エッジ数、`legend`
（どの属性をどのチャネルに割り当てたか）、`layout_quality`（重なり・交差などの
読みやすさ）だけである。`visualization_get_state` は保存された設定を返すだけで、
何がどこに描かれているかは返さない。

そのため「コミュニティ A は左上にまとまっている」「中心性の高いノードは中央にある」
「色のグループが混ざっていて区別できない」といった、利用者が図を見て真っ先に
受け取る空間的な事実を、エージェントは画像なしに確かめられない。説明や次の
エンコーディングの提案が、図と食い違ったまま進むことがある。

## 決定

1. 読み取り専用の MCP ツール `visualization_describe` を加える。描画と同じ
   データ（`build_visualization` が返す座標・色・サイズ・ラベル・ハイライト）から
   次を計算して返す。
   - **概要**: レイアウト名、描画中のノード数・エッジ数、座標系の説明。
   - **領域**: 描画を 3×3 に分けた各領域のノードの割合と、空いている領域。
   - **グループ**: カテゴリ属性（既定は色に割り当てた属性、`group_by` で指定可）の
     値ごとに、ノード数・重心・領域・広がり・まとまり（近傍 5 ノードのうち
     同じグループの割合）。全体の `separation`（0 = 無作為に混ざっている、
     1 = 完全に分かれている）。
   - **数値の配置**: サイズと連続色に割り当てた属性について、値の大きいノードが
     どの領域にあるか、値と「中心からの近さ」の順位相関。
   - **目立つノード**: 描画サイズの上位ノードと、中心・中間・周辺のどこにあるか。
   - **連結成分**: 成分数、孤立ノード数、大きい成分の位置と広がり。
   - **外れ値**: 最近傍までの距離が他より極端に大きいノード。
   - **ハイライトとラベル**: ハイライト中のノードの位置、ラベルを表示しているノード。
   - **読みやすさ**: `layout_quality` をそのまま含める。
2. 結果の大きさはネットワークの規模に比例させない（ADR 0024）。一覧は `limit` 件まで
   返し、省略した件数を明記する。
3. 結果に `nodes` / `links` を含めない。含めると描画の更新として扱われ、
   キャンバスに送られてしまう（`on_visualization_payload`）。
4. 計算は `networkx-api/app/logic/drawing_description.py` の純粋関数に置き、
   ツールはデータを集めて渡すだけにする。

## 根拠

- 座標は `normalize_like_renderer` で正規化された、キャンバスに描かれるのと同じ値を
  使う（ADR 0017 と同じく「描かれた所で測る」）。y 軸は SVG と同じく下向きなので、
  y が負の側を「上」と呼ぶ。
- ビューポート（ズーム）は保存されない一回限りの指示なので（ADR 0023）、
  説明は常に全体図を基準にする。ツールの説明にもそう書く。
- 位置を座標の数値だけで返すと、モデルが図の形として解釈しにくい。3×3 の領域名
  （"top-left" など）と、中心からの距離による「中心・中間・周辺」の区分を併記する。
- グループの分離は、近傍のうち同じグループの割合を、偶然の期待値（そのグループの
  占める割合）で補正した値で表す。大きいグループほど偶然でも近傍が同じになるので、
  補正しないと大きいグループが「まとまっている」と誤読される。

却下した代替案:

- **`visualization_generate` の結果に毎回含める**: 描画のたびに観測が大きくなり、
  後のターンで履歴として再送される（ADR 0024 の過去観測の予算）。必要なときだけ
  呼べる別のツールにした。
- **画像を生成してマルチモーダルで渡す**: プロバイダごとに扱いが異なり、トークン量も
  大きい。数値で言える事実は数値で渡す方が、確かめやすく再現性もある。
- **`visualization_get_state` を拡張する**: 設定を返すツールと描画を測るツールでは
  費用（描画の再構築と交差の計算）が大きく違う。名前で区別できる方がよい。

## 帰結

- `visualization_describe` は描画を一度組み立てる（`build_visualization`）。
  保存済みの設定を読み直すだけで、設定は変えない。
- 領域の閾値（3 等分）、近傍数、中心・周辺の境界、外れ値の倍率はコードの定数に置く。
- 実装: `networkx-api/app/logic/drawing_description.py`、
  `networkx-api/app/mcp/tools/visualization/state.py`。
