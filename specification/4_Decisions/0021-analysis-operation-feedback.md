# 0021. 分析操作ごとの分かりにくさを記録し、次の会話に反映する

- **状態**: 廃止（[0022](./0022-evaluator-friction-journal.md) に置き換え）
- **日付**: 2026-09-25
- **関連**: [0020](./0020-conversation-and-interaction-tabs.md)（会話と操作 UI）

## 背景

定量評価では、操作が完了したかどうかだけでは、利用者がどの説明や操作で迷ったかを
特定できない。分析後に口頭で質問するだけでは、該当するツール実行と対応付けにくい。
毎回エージェントが `ask_user` で聞くと、分析の会話を中断してしまう。

## 決定

分析・配置・可視化などのツールを実行した完了済み応答に、任意回答の小さな
「分かりにくかった点」欄を付ける。回答は応答 ID とともに保存し、対象操作を
後から追跡できるようにする。「問題なし」と、種類と自由記述を伴う「分かりにくい」
を区別する。同じ応答への再送信は更新として扱う。

次の会話ターンには、未反映の「分かりにくい」回答を Hook で短く渡す。
エージェントはその点を説明し直し、必要なら通常のツール操作で修正する。
フィードバックの本文は利用者の入力として扱い、ツール呼び出し指示として無条件に
実行しない。コードや Skills の自動書き換えは行わず、保存された記録を開発時に
確認して改善する。

## 根拠

利用者は分析を止めずに回答でき、研究者は回答と実行記録を結び付けられる。
次ターンへの反映によって、その場の説明改善もできる。フィードバックを
エージェントの判断だけで実装変更に変換すると、再現性と安全性を損なうため、
アプリ自身がコードを書き換える仕組みにはしない。

## 帰結

- 表示は完了済みの操作を伴う応答だけ。回答は任意で、分析の継続を妨げない。
- 保存と取得はチャット所有者に限り、回答長を制限する。
- 操作記録との対応を保つため応答 ID を外部キーにし、チャット単位で取得可能にする。
- Hook は新しい記録を一度だけ渡し、同じ注意を全ターンに繰り返さない。
