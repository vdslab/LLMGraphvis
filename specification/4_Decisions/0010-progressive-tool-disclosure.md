# 0010. ツール定義をターン内で段階的に公開する

- **状態**: 採用
- **日付**: 2026-09-11

## 背景

MCP が公開するツールが増え、要求と無関係な定義まで毎回 LLM に送るコストが
大きくなった。MCP の一覧キャッシュは通信を減らすが、モデル入力の量は減らさない。

## 決定

Backend は全定義をカタログとして保持し、各ターンの最初には `skill_load`、
`tool_search`、`ask_user` だけを公開する。スキルを読むと `related_tools` を、検索を
行うと検索結果を、そのターンの次回 LLM 呼び出しから追加する。状態はターン間で
共有しない。比較と切り戻しのため `TOOL_EXPOSURE_MODE=all` を残す。

検索はツール名、説明、スキルの説明と日英トリガーを対象とする決定的なローカル検索
とし、追加のモデルや外部サービスを必要としない。非推奨ツールは完全一致でのみ返す。

## 根拠

既存の Skills は手順を遅延取得し、必要なツール名を `related_tools` に持っている。
同じ境界を定義公開にも使うことで、手順と実行能力を一緒に取得できる。検索を併設し、
スキルに属さない機能や将来追加されるツールにも到達可能にする。

## 帰結

モデルに見えていないツールは機能が存在しないことを意味しない。未公開ツールの呼出し
は実行前に保留され、検索またはスキル読込を案内される。公開集合は同一ターンでは増加
のみで、並行するチャットには影響しない。定義の件数とバイト数を各 LLM 呼出しで記録し、
入力トークンや完了率とは別の測定値として扱う。
