# 0020. 会話と操作 UI をチャット欄の中で切り替える

- **状態**: 採用
- **日付**: 2026-09-25
- **関連**: [0004](./0004-conversation-inputs.md)（入力要求）、[0016](./0016-parameter-tuning.md)（調整パネル）

## 背景

`ask_user` の選択 UI とパラメーター調整パネルはツール実行の位置にそのまま表示される。
会話が長いと操作対象を見失いやすく、狭いチャット欄ではフォームが前後の説明と混ざる。
一方、選択肢にない答えや数値の調整を言葉で伝える経路は必要である。

## 決定

新しい入力要求または調整パネルが最新の応答に添えられたとき、チャット欄に
「会話」と「操作 UI」のタブを出し、操作 UI 側を開く。利用者はいつでも会話に戻り、
自由文で答えられる。フォームの永続状態・送信先・再実行手順は既存のまま使う。

会話側には説明文を残す。現在別タブに表示している UI だけを会話の実行記録から
重複表示しない。新しい発話を送ったら会話に戻る。古い操作 UI は履歴上で従来どおり
確認できる。

## 根拠

フォームを大きく表示しても、会話での操作を並列の入口として残せる。
履歴の保存形式や SSE 契約を変えず、既存の `InputRequest` と `ParameterTuning` の
サーバー状態確認をそのまま利用できる。

却下した代替案:
- **常にフォームをチャットから取り除く**: 過去の選択や調整を履歴から追えなくなる。
- **別ウィンドウを開く**: 図と会話との対応が分かりにくくなる。

## 帰結

- 最新の応答に添えられた UI の識別子で、二重表示と自動切替を制御する。
- UI タブがないときは従来の会話欄を表示する。保存済みの古い UI は履歴に残す。
- タブはキーボードで選べ、フォームから会話へ戻る入口を常に表示する。
