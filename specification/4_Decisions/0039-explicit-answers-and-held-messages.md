# 0039. 質問への回答は明示し、質問の前に書かれたメッセージは保留する

- **状態**: 採用
- **日付**: 2026-10-23
- **関連**: [0004](./0004-conversation-inputs.md)、[0020](./0020-conversation-and-interaction-tabs.md)、[0037](./0037-chat-rendering-and-stream-resync.md)

## 背景

ターン実行中も入力欄は使え、送ったメッセージは `queued` として保持され、
ターン終了時に自動送信される。一方バックエンドは、`input_request_id` の無い
通常メッセージでも、未回答の質問があればその回答として受け付けていた。

2026-10-23 のチャット 280 では、モデルが色分けの質問を保存した 0.1 秒後に、
利用者がターン中に書いた「中心性でレイアウトを再計算したい」が自動送信され、
色分け質問の回答として記録された。利用者は質問を見る前に書いたメッセージであり、
回答の意図は無い。

## 決定

1. **回答は明示する。** バックエンドは `input_request_id` が指定されたときだけ
   メッセージを質問への回答として扱う。指定の無い通常メッセージが届いたとき、
   未回答の質問は `superseded` にし、メッセージは新しい依頼として処理する。
2. **質問が見えている状態で入力欄から送った文は、その質問への回答である。**
   フロントエンドは送信時点で最新の応答に未回答の選択式質問があり、ターンが
   終わっていれば、その id を付けて送る。入力欄の案内文も回答用に変える。
3. **質問より前に書かれたメッセージは自動送信しない。** ターンが質問または
   調整パネルで終わったとき、`queued` のメッセージは `held` にする。利用者が
   「新しい依頼として送る」「回答として送る」（選択式質問のときのみ）「取り消す」
   を選ぶまで送らない。
4. 最新の操作 UI を探すときは、まだサーバーに届いていない（`queued`・`held`・
   `failed`）メッセージを飛ばす。末尾にあるそれらのせいで質問タブが消えないようにする。

## 根拠

- **送信時刻と質問の作成時刻を比べてサーバー側で判定する案**は却下した。時計の
  ずれと通信遅延があり、「利用者が質問を見たか」は画面側でしか分からない。
- **ターン中は入力を禁止する案**は却下した。入力欄を塞がないことは
  `Composer` の設計判断であり、問題は送る時点の解釈にある。
- **保留せず常に新しい依頼として送る案**も採らなかった。質問を読んだ後なら
  回答として送りたい場合が多く、選択を利用者に残す方が意図に沿う。

## 帰結

- 質問への回答経路は「フォーム送信（`input_values` 付き）」と「入力欄から
  `input_request_id` 付きで送る自由文」の 2 つだけになる。暗黙の紐付けは無い。
- 実装: `backend/app/api/v1/endpoints/chat.py`（`process_message`）、
  `frontend/src/stores/chatStore.js`（`held` 状態と `dispatchQueued`）、
  `frontend/src/utils/chatInteraction.js`、`frontend/src/components/chat/Composer.jsx`。
