# 0028. 表示を版として記録し、会話の任意の時点の表示に戻せるようにする

- **状態**: 提案
- **日付**: 2026-09-29
- **関連**: [0016](./0016-parameter-tuning.md)（調整セッション）、[0023](./0023-view-navigation-and-labels.md)（視点は保存しない）

## 背景

表示の状態は「今」しか保存されていない。

- スタイル（色・サイズ・ラベル・辺・ハイライト）は `networks.last_*_config` に上書きされる。
- 座標はレイアウト名ごとの属性 `{layout}_x` / `{layout}_y` に上書きされる。同じ
  アルゴリズムを別のパラメーターで再計算すると、前の配置は失われる。
- `chats.visualization_state` は最後に描画したペイロード1つだけである。
- 各ツール呼出しは `tool_executions` に引数付きで残るが、結果は切り詰められており、
  表示を復元する材料にはならない。

そのため「3つ前の配色に戻して」「コミュニティで塗った時の表示に戻して」は、
エージェントがツールを呼び直して再現するしかない。座標が上書き済みなら、同じ
seed で再計算できる場合を除き、元の配置は再現できない。調整セッション（0016）の
履歴はパラメーター値の履歴であって、表示そのものの履歴ではない。

研究の観点では、どの操作列がどの表示を生んだかを後から辿れること（来歴）も必要である。

## 決定（案）

1. **表示版 `view_versions` を導入する**。1版は次を持つ。
   - `chat_id`、`network_id`、`message_id`（その版を生んだアシスタント応答）、`created_at`
   - 6つのスタイル設定（`last_*_config` の写し）と `last_layout_name`
   - 座標のスナップショット `{node_id: [x, y]}` と、そのレイアウトのキャッシュ用
     `computation_params`
   - 内容ハッシュ（同一内容の版を重複して作らないため）
   視点（ズーム・パン）は 0023 に従い保存しない。
2. **版はターン単位で作る**。TURN_END フックが、そのターンで表示が変わった場合に
   1版を記録する。ツール呼出しごとには作らない。ユーザーが見て話題にするのは
   応答ごとの表示だからである。調整パネルの「適用」も1版とする。
3. **戻す操作は新しい版を作る**。復元は設定と座標を書き戻し、ネットワークが
   違えばアクティブネットワークも切り替え、再描画し、「版 N から復元」という新しい
   版を記録する。履歴は書き換えないので、戻す操作も取り消せる。
4. **経路は二つで、同じ処理を通る**。
   - 画面：表示を変えたアシスタント応答に「この表示に戻す」ボタンを付ける。
   - 会話：ローカルツール `view_list_versions` と `view_restore` を追加し、
     「さっきの表示に戻して」を扱えるようにする。手順は Skill `view-history` に書く。
5. **来歴は版から辿る**。版は `message_id` を持つので、その版までの
   `tool_executions` がそのまま生成手順になる。書き出し（JSON／Markdown）は第2段階とする。

## 根拠

- ツールを呼び直して再現する方式（0016 の replay と同じ）は、座標が上書き済みの
  場合や、途中でサブグラフを作った場合に元へ戻れない。スナップショットなら確実に戻る。
  1,000ノードで約20KBなので、ターンごとに保存しても負担は小さい。
- 描画ペイロード全体の保存は、ノード・辺の全属性を含み大きい。設定と座標だけで、
  `visualization_builder` が同じ表示を再構成できる。
- 復元で履歴を切り詰める方式（一般的な undo スタック）は、戻した後に元の版へ
  進めなくなる。会話の履歴は消えないので、表示の履歴も消さないほうが整合する。

## 帰結

- スキーマ変更（Alembic リビジョン）が要る。
- 復元は座標属性とキャッシュメタデータを書き戻すので、復元後の同じパラメーターでの
  レイアウト呼出しはキャッシュに当たる。
- 派生属性（中心性・コミュニティ）は版に含めない。色やサイズがそれらを参照する場合、
  属性が再計算で変わっていれば、復元した表示の色分けは現在の値で描かれる。
  完全な再現が必要なら、参照属性の値も版に含める（未決）。
- サブグラフは削除されないので、別ネットワークの版にも戻れる。
