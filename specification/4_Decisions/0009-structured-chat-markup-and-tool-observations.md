# 0009. チャット構造を Markdown directive と軽量な観測結果に分離する

- **状態**: 採用
- **日付**: 2026-09-11

## 背景

保存済みメッセージは Markdown 本文の中に HTML 風の独自タグを埋め込み、
フロントエンドが正規表現で分割していた。モデルが契約にない
`<visualization_output .../>` を本文へ書くと通常テキストとして露出し、タグの表記揺れや
未完のストリームにも個別対応が必要だった。

また、可視化ツールの完全なノード・リンク配列は SSE でキャンバスへ送る必要がある一方、
同じ配列を LLM の観測結果と履歴にも入れていた。モデルが次の判断に必要なのは描画の成否と
要約であり、完全な描画ペイロードではない。さらに、既にツールを実行したターンの完了報告を
「未実行の宣言」と誤認し、不要な生成をもう一周行う場合があった。

## 決定

新しく生成する永続的なチャット構造は CommonMark generic directives で表す。
フロントエンドは `react-markdown` の remark パイプラインに `remark-directive` と
`unist-util-visit` を組み込み、既知の directive を型付きのチャット部品へ変換する。
既存会話の HTML 風タグは読み取り互換として残すが、新規には生成しない。契約外の内部制御タグは
表示しない。

ツールの実行結果は用途を分離する。POST_TOOL フックと `render_update` は完全な結果を受け取り、
LLM と永続化された ToolExecution には意味を保つ軽量な観測結果だけを渡す。可視化結果では
ノード・リンク配列を件数へ置き換え、ネットワーク ID、凡例、その他の小さなメタデータは残す。

未実行の宣言を再開させるフックは、そのターンでツールが一度も成功していない場合にだけ働く。

## 根拠

directive は Markdown の構文木として解析でき、文字列の空白・改行・属性順へ依存する正規表現を
新しい契約から排除できる。`rehype-raw` で任意 HTML を実行可能にする案は、モデル出力を DOM として
解釈する必要がなく、安全面の負担が増えるため採用しない。

描画データを一律の文字数で切るだけでは、少数のノード・リンクが依然として大きく、モデルに
必要な情報と不要な情報を区別できない。用途別に意味を保って圧縮することで、キャンバスの忠実性を
落とさず会話コンテキストだけを減らせる。

## 帰結

- 新しいインバンド構造は Markdown directive とし、バックエンドとフロントエンドを同時に変更する。
- 旧 HTML 風タグは履歴表示のためにのみ受理する。
- モデル出力に現れた契約外の内部タグはユーザーへ表示しない。
- UI 用の完全なツール結果と、LLM 用の観測結果を同一視しない。
- ツールを実行済みの完了報告だけを理由に ReAct ループを延長しない。

実装は `backend/app/services/llm/markup.py`、`engine.py`、`hooks/builtin/intent.py`、
`frontend/src/utils/parseMessageContent.js` に現れる。
