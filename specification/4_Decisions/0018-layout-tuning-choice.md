# 0018. レイアウトを描いた直後に、調整の進め方を3択で尋ねる

- **状態**: 採用
- **日付**: 2026-09-18
- **関連**: [0004](./0004-conversation-inputs.md)（入力要求）、[0014](./0014-activation-survives-a-question.md)（回答をまたぐ公開状態）、[0016](./0016-parameter-tuning.md)（パラメーター調整）、[0017](./0017-layout-quality-metrics.md)（レイアウト品質）

## 背景

0017 でエージェントは描いたレイアウトの品質を数値で知り、`layout_suggest_parameters` で
改善候補を探せるようになった。しかし、それを使うかどうかはユーザーが「見づらい」と
言い出すまで分からない。力学レイアウトの見え方はパラメーターで大きく変わるのに、
ユーザーは調整できることを知らないまま次の分析に進みがちである。

一方で、改善を黙って自動適用すると、ユーザーが見ていた図が断りなく変わる（User Agency）。
調整パネルを毎回出すのは、数値を扱わない利用者には負担が大きい。

## 決定

1. **エージェントが力学レイアウト（forceatlas2 / spring / arf）を描いた直後に、
   調整の進め方を `ask_user` の3択で尋ねる。** 選択肢は「おまかせで調整」
   「今の値から自分で調整」「このままでよい」。尋ねる前に `layout_quality` の状態を
   1〜2文で伝える。問題が無ければそう伝えたうえで尋ねる。
2. **尋ねるのは、そのチャットでこのネットワークに初めてレイアウトを実行したときと、
   アルゴリズムを変えたときだけ。** 同じアルゴリズムの再実行では尋ねない。
3. **ユーザーがパラメーターを指定したレイアウトでは尋ねない。** すでに自分で調整して
   いるためで、従来どおり調整パネルの提案（0016）に任せる。
4. **アップロード時とサブグラフ作成時の自動レイアウトは対象外にする。** これらは
   エージェントのターンの外（またはサブグラフ作成の副作用）であり、完全に自動でよい。
   アップロード直後の自動レイアウトは「初めて」に数えないので、その後にユーザーが
   レイアウトを頼めば尋ねる。
5. 各選択肢の手順は `layout` スキルが持つ。
   - おまかせ: `layout_suggest_parameters` の最良候補がスコアを改善するなら適用して
     再描画し、変更したパラメーターと見え方の変化を報告する。改善しなければそう伝える。
   - 自分で調整: `layout_suggest_parameters` の `knobs` を範囲、最良候補を推奨値として
     調整パネル（`offer_parameter_tuning`）を出す。
   - このまま: 何もしない。
6. 強制は NO_TOOL_CALLS フックで行い、1ターン1回に限る。モデルが自分で尋ねた場合や
   すでに調整を始めている場合は何もしない。

## 根拠

0016 は「パラメーターの値を `ask_user` で聞かない」と決めている。今回の3択は値ではなく
**調整の進め方**を選ぶものであり、この決定と矛盾しない。値を尋ねるフォームは試行錯誤の
たびに LLM 往復が要るが、進め方の選択は描画直後に1回だけで、その後は言葉・パネル・
自動探索のいずれかに引き継がれる。

尋ねる機会を「初回とアルゴリズム変更時」に絞ったのは、同じアルゴリズムの再実行は
ユーザーがすでに見え方に関わっている場面であり、毎回尋ねると会話の妨げになるため。
品質に問題が無くても尋ねるのは、指標が捉えない好み（もっと詰めたい、広げたい）が
あり得るためで、その場合も1回で済む。

自動で最良候補を適用しないのは、図が断りなく変わるのを避けるため（0016 の
「推奨値は自動適用しない」と同じ理由）。「おまかせ」はユーザーの明示的な委任である。

却下した代替案:
- **候補から選ぶ（4択目）**: 文字だけの候補説明では選びにくく、サムネイル表示は
  フロントエンドの作業が大きい。必要が確かめられてから追加する。
- **問題があるときだけ尋ねる**: 指標が捉えない好みを取りこぼす。
- **アップロード時の自動レイアウトでも尋ねる**: ターン外であり、アップロードは
  完全自動でよい。
- **スキルの記述だけで促す**: 0016 と同じく、小さなモデルは締めの文で終えやすく、
  フックでの促しが要る。

## 帰結

- 力学レイアウトの集合はフック側の定数で持つ。`knobs` を持つレイアウトを増やしたら
  この集合も更新する。
- 「初めて」の判定は、このチャットで保存済みのツール実行（前のターン）と、
  このターンの実行記録から行う。保存済みの引数に `network_id` が無い呼び出しは
  現在の表示に対するものとみなす（0016 と同じ扱い）。
- 回答は次のターンで届く。`layout` スキルに「おまかせ」等の語をトリガーとして持たせ、
  回答のターンでも手順が参照されるようにする。
- 実装: `backend/app/services/llm/hooks/builtin/tuning.py`（`nudge_layout_choice`）、
  `skills/definitions/layout.md`。
