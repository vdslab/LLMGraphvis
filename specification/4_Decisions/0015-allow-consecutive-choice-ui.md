# 0015. 回答再開ターンでの分析後の選択肢提示を許可する

- **状態**: 採用
- **日付**: 2026-09-15

## 背景

ユーザーが選択用UI（`ask_user`）に回答した後、エージェントが分析・スタイリングを実行し、その結果を踏まえて次の可視化や追加分析の選択肢を提示しようと2回目の `ask_user` を呼び出す場面がある。
しかし、従来の `guard_redundant_question` フックが、回答再開ターン（`resumed_from_input=True`）でのツール実行後（`tools_run >= 1`）の `ask_user` を一律で保留（defer）していた。
その結果、2回目の選択用UIが表示されず、エージェントがシステムからの指示に従って勝手に「承知しました。現在のビューを維持します」と自己解決して終了してしまい、ユーザーが選択・確認できない問題が発生していた。

## 決定

`guard_redundant_question` フックを廃止し、回答再開ターンにおいて分析ツールが実行された後でも、次の選択肢を提示するための `ask_user` 呼び出しを許可する。
説明文を伴わない形式だけの質問提示は、既存の `guard_question_needs_prose` フックによって引き続き防止する。

## 根拠

分析方針の選択（第1段階）を経てツールを実行し、その結果をもとに次の可視化方針やサブグラフ展開等の選択肢を提示する（第2段階）フローは、対話型ネットワーク可視化分析において自然かつ本質的なUXである。
質問ツール（`ask_user`）が実行されると、エンジンは即座にターンを終了して利用者の入力を待つため、無限ループや暴走のリスクは存在しない。
このガードを削除しても、説明文の存在確認（`guard_question_needs_prose`）やUI側の入力検証・重複送信防止によって安全性と対話の品質は担保される。

## 帰結

- 回答再開ターンにおいて、分析ツールの実行後に2回目の選択用UI（`InputRequest`）が正常に生成・表示される。
- 利用者は連続する分析ステップにおいて、各段階の分析結果を確認しながら次のアクションを自身で選択・決定できるようになる。
