# 0003. 分析操作とパラメーターを明示的な契約にする

- **状態**: 採用
- **日付**: 2026-09-10

## 背景

会話による分析では、引数が無視されても利用者が気づきにくい。複数の
アルゴリズムを一つの引数集合にまとめると無効な組み合わせが増え、抽出に
表示切り替えが付随すると分析対象も意図せず変わる。

## 決定

採用する NetworkX のバージョンを固定し、公開パラメーターを実際の計算へ
渡す。対応しない指定は理由付きで拒否する。APIとの差分はコードとテストで
管理し、2D描画や永続化との違いは説明文に明記する。

アルゴリズムごとに型付きのツールを提供する。分析、抽出、表示対象の変更、
描画を独立させ、旧来の複合ツールは互換経路として維持する。
計算結果の保存属性名と実際に使用した設定を返し、キャッシュにも反映する。

## 根拠

任意のPython関数やkwargsを受け付ける汎用実行ツールでは、モデルが有効な
操作を判断しにくい。型と説明を持つ個別ツールなら、引数検証、再現性、
エラー回復の基準を同じ契約に揃えられる。

## 帰結

NetworkX更新時は対応範囲の検査を必要とする。ツールの数が増えても、手順は
Skills、制約はロジック、説明はdocstringに集約する。重複する保存や検証処理を
共通化し、アルゴリズム別の分岐が複数箇所に散らばるのを避ける。
