# 会話によるネットワーク分析の定量評価案

## 目的

初心者とネットワーク分析経験者が、同じ分析結果に会話だけで到達できるかを測る。
操作時間だけでなく、誤った解釈や意図しない可視化も失敗として記録する。

## 実施条件

- 参加者を事前質問で初心者群と経験者群に分ける。ネットワーク分析経験と、
  中心性・コミュニティ検出・レイアウトの理解を別々に尋ねる。
- 全員が同じブラウザ幅と同じ LLM モデルを使い、各課題を新しいチャットで開始する。
  課題とデータセットの順番は参加者間で入れ替える。
- 課題文は分析の目的だけを伝える。初心者にアルゴリズム名を強要せず、
  経験者が具体的な手法やパラメーターを指定することは許す。
- 開始時刻、各発話、ツール実行、描画結果、終了時刻を保存する。
  操作直後の任意フィードバックは応答 ID でツール実行と結び付ける。

## 課題候補

| 課題 | 達成した状態 | 確認する点 |
|---|---|---|
| 属性から集団を読む | Karate Club の記録済み集団でノードを色分けし、凡例から各集団を読める | 元データの属性と計算したコミュニティを混同しないか |
| 重要なノードを探す | 同じネットワークで橋渡し役を特定し、根拠になる中心性と図を示す | 初心者には意味を説明し、経験者の手法指定には従うか |
| 配置を改善する | 重なりなどの問題を確認し、会話または調整パネルで配置を変える | 品質情報の発見、パラメーターの効果、変更前後の説明 |
| 集団の細かさを比べる | Les Misérables で二つのコミュニティ粒度を比較する | 設定値と結果を混同せず、同じ図へ再適用できるか |

## 記録と判定

各課題について、成功を「達成した状態が図と説明の両方で確認できる」と定義する。
判定者はチャット本文だけでなく、保存されたツール名・引数・結果と最終描画を照合する。
部分成功（結果は得たが説明が誤る等）と失敗を別に記録する。

主要指標は課題成功率と完了時間。補助指標は発話回数、やり直し回数、ツール失敗数、
利用者が操作を中断した回数とする。評価役AIの操作上の迷いは別の評価記録に残す。
時間切れの課題は未完了として扱い、
完了した課題だけの平均時間を成功率と切り離して示す。

開始前に評価者が正解条件と許容する代替手法を固定する。モデルや Skills を評価中に
更新した場合はバージョンを分けて集計する。自由記述の回答はそのまま公開せず、
個人を識別しうる情報を除いて分析する。
